# Добавление аудиофрагмента

Проводит новый аудиофайл через весь путь: от исходника до готовой карточки в данных.

## Ключевые принципы

**Теги внутри файла — единственный источник правды.** При отправке аудио по `file_id`
Telegram показывает метаданные закешированного файла и игнорирует параметры `title`
и `performer` из кода. Прикрыть неудачные теги на стороне бота нельзя.

**Спойлер убираем, атрибуцию сохраняем.** Вычищаются только поля, выдающие ответ.
Сведения о правах (`artist`, `comment`, `copyright`) остаются нетронутыми — это условие
лицензии используемых записей. Никогда не применять `-map_metadata -1`.

**Аудио не хранится в репозитории.** Файлы живут на серверах Telegram, в карточке
лежит только строка `file_id`.

## Шаг 1. Уточнить исходные данные

Спросить у пользователя, если не сказано:

- путь к исходному файлу;
- исполнитель и источник записи (для поля `recording`);
- подтверждение, что лицензия допускает использование.

## Шаг 2. Подготовить файл

Запустить скрипт из этого скилла:

```bash
.claude/skills/add-fragment/prepare.sh "<путь к исходнику>" prepared/<id карточки> <начало> <длительность>
```

Файл всегда называется `fragment.mp3`, различаются только папки — по `id` карточки.
Telegram показывает имя загруженного файла, поэтому у всех карточек оно должно
выглядеть одинаково: нумерованные имена выдают, что фрагментов много, и мозолят глаз.

Скрипт покажет теги до и после, вырежет нужный кусок, уберёт обложку и главы,
задаст нейтральный `title="Фрагмент"` и очистит `album`, сохранив всё остальное.

Исходники обычно содержат произведение целиком, поэтому обрезка нужна почти всегда.
Разумная длительность фрагмента — 30–40 секунд. Начало берётся с `0`, если
узнаваемая тема звучит с первых тактов; иначе нужно уточнить у пользователя,
какой именно эпизод брать.

Изучить вывод и проверить, не остались ли спойлеры в полях `comment` или `description`.
Если остались — доочистить точечно, перечисляя конкретные поля, а не снося всё разом.

Напомнить пользователю: тильда `~` внутри кавычек не раскрывается, путь с ней нужно
писать как `~/"Desktop/файл.mp3"`.

## Шаг 3. Получить file_id

Это шаг пользователя, автоматизировать нельзя. Попросить его:

1. запустить бота: `source .venv/bin/activate && python main.py`;
2. отправить боту `fragment-NN.mp3` личным сообщением;
3. скопировать `file_id` из ответа хендлера `audio_file_id`.

`file_id` привязан к конкретному боту: при смене токена идентификаторы придётся
получать заново.

## Шаг 4. Заполнить карточку

Внести в `data.py`:

```python
"audio_file_id": "<новый file_id>",
"recording": {
    "performer": "<исполнитель>",
    "source": "<источник>",
},
```

## Шаг 5. Проверить

Попросить пользователя перезапустить бота и открыть «🎲 Случайный квиз». Проверить:

- в плеере отображается «Фрагмент — <исполнитель>» без намёка на ответ;
- имя файла в сообщении нейтральное;
- после ответа приходит факт и строка «🎧 Запись».
