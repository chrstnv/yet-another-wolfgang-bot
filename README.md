# yet-another-wolfgang-bot

Телеграм-бот, который учит узнавать классическую музыку на слух. Играет фрагмент,
предлагает четыре варианта, а после ответа рассказывает, что это было, — и даёт
факт, ради которого всё и затевалось.

Ведёт квиз Вольфганг Амадей Моцарт: самовлюблённый, язвительный и убеждённый, что
лучший выбор музыки — его собственный.

## Как устроено

Код и контент лежат в разных репозиториях. Здесь — бот, отдельно и приватно —
карточки с аудио: их около полутора сотен, и на каждую заведён свой JSON.

```
   main.py              сборка приложения и роутинг
   core/                ничего не знает про Telegram
      content.py        чтение библиотеки и её проверки
      quiz.py           отбор карточек, ловушки, порядок вопросов
      progress.py       сборка подписей и итогов
      storage.py        SQLite: ответы, рекорды, отправленные аудио
      texts.py          все тексты бота
   bot/                 переходник к Telegram
      handlers.py       экраны, кнопки, ретраи
      keyboards.py      меню
   tools/               добавление карточек и проверка библиотеки
   hooks/               проверки перед коммитом
   docs/                концепция и отложенные идеи
   .claude/             спеки агента и навыков
```

Граница между `core` и `bot` — главное свойство этой структуры. Ни один модуль из
`core` не импортирует Telegram, поэтому его тесты пишутся без единого мока бота, и
их почти две сотни. Захочется веб-версии — менять придётся только `bot`.

## Запуск

Нужен Python 3.14 и токен от [@BotFather](https://t.me/BotFather).

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # и заполнить BOT_TOKEN с CONTENT_PATH
python main.py
```

Без `CONTENT_PATH` бот не стартует и скажет об этом: библиотека карточек живёт
в соседнем репозитории, и путь к ней надо назвать явно.

## Работа с библиотекой

```bash
python -m tools.check_content            # проверить карточки
python -m tools.check_content --record   # принять текущие числа за норму
python -m tools.add_card --help          # добавить карточку или перерезать фрагмент
```

`check_content` делит найденное надвое. **Поломки** — то, без чего бот не
запустится: карточка без названия, фрагмент без аудио, запись без имени
исполнителя. **Изъяны** — то, что портит подпись, но работать не мешает: описание
пересказывает факт, факт длиннее двух предложений, лицензия записи не записана.

Изъяны не требуют нуля: у библиотеки есть накопленный долг, и требование нуля
означало бы, что проверку отключат в тот же день. Вместо этого числа записаны
в `tools/flaws_baseline.json`, и проверка падает, когда какое-то из них выросло.

## Тесты и хуки

```bash
python -m pytest              # 188 тестов
sh hooks/install.sh     # хуки перед коммитом в оба репозитория
```

Хук в этом репозитории гоняет тесты и проверку библиотеки, хук в репозитории
с контентом — только проверку. Обойти можно через `git commit --no-verify`.

## Правила контента

Записи берутся только те, которые разрешено использовать некоммерчески **с
указанием авторства**, поэтому у каждого играющего фрагмента есть исполнитель и
источник — это проверяется как поломка. Записи под лицензией с NoDerivatives
нельзя резать: такие заливаются целиком.

Как искать записи и как готовить фрагменты — в `.claude/skills`. Как писать
факты — в `.claude/agents/fact-finder.md`, а рядом лежит список историй, которые
уже проверялись и не прошли.
